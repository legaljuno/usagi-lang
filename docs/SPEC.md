# 우사기랭 명세 v0.2

우사기랭(Usagi Lang)은 정수 기반의 난해한 프로그래밍 언어다. 소스 파일 확장자는 `.usa`다. CLI와 플레이그라운드는 같은 인터프리터를 사용한다.

## 프로그램 구조

- 소스는 해석 전 Unicode NFC로 정규화한다. 오류의 행과 열은 정규화된 텍스트를 기준으로 1부터 센다.
- 한 줄에 명령 하나를 쓴다. 공백과 빈 줄은 무시하고 `#`부터 행 끝까지는 주석이다.
- 첫 명령은 `야하!`, 마지막 명령은 `우라라!`여야 한다. 두 명령 뒤에 수식은 올 수 없다. 종료 뒤의 명령도 오류다.
- `야하!`를 제외한 본문의 첫 명령이 1번이고, `우라라!`는 마지막 명령 번호에 포함된다. 빈 줄과 주석은 번호를 차지하지 않는다.

## 수식

수식의 모든 항을 왼쪽에서 오른쪽으로 더한다. 수식에는 공백을 넣을 수 있으며 공백 없이도 토큰을 이어 쓸 수 있다. 가장 긴 유효 토큰을 먼저 인식한다.

| 토큰 | 값 |
| --- | --- |
| `야` | +1 |
| `하` | −1 |
| `야하` | +1 (한 토큰) |
| `이+히+` | `이`의 개수. `히`의 개수는 값에 영향 없음 |
| `라+` | `라` 개수에 해당하는 변수의 값 |

따라서 `야하`는 1이고 `야 하`는 0이다. `이히히 야하 이이히`는 4이다. 변수는 모두 정수이며 아직 대입하지 않은 변수의 값은 0이다. 각 덧셈의 중간 결과를 포함해 JavaScript 안전 정수 범위(−9,007,199,254,740,991 ~ 9,007,199,254,740,991)를 벗어나면 실행 오류가 발생한다.

## 명령

명령 접두부와 수식 사이의 공백은 선택 사항이다. 아래의 `+`와 `?`는 정규표현식의 반복 기호이고 소스에 그대로 적는 기호가 아니다. 단 `하아?`와 `야하?`의 물음표는 실제 명령의 일부다.

| 명령 | 동작 |
| --- | --- |
| `야하!` | 프로그램 시작 |
| `우라라!` | 프로그램 종료 |
| `우+ <수식>` | `우` 개수에 해당하는 변수에 수식 값을 대입. 빈 수식은 0 |
| `우라! <수식>` | 정수와 개행 출력 |
| `이?야아+하아+! <수식>` | 정수와 개행 출력. 길이가 달라도 동작은 같다 |
| `푸루루! <수식>` | 유효한 유니코드 스칼라 값을 문자 하나로 출력, 개행 없음. 빈 수식이면 개행만 출력 |
| `하아? <수식>` | 값이 0이면 다음 명령 실행, 0이 아니면 다음 명령 하나를 건너뜀 |
| `야하? <수식>` | 수식의 결과에 해당하는 1부터 시작하는 명령 번호로 이동 |

숫자 출력, 랩 출력, 조건문, 점프에는 수식이 필요하다. 점프가 명령 범위를 벗어나거나 조건문이 종료 명령을 건너뛰어 프로그램 밖으로 나가면 실행 오류다. 유니코드 문자는 `0`~`0x10FFFF` 중 서로게이트(`0xD800`~`0xDFFF`)를 제외한 값만 허용한다.

명령 접두부를 인식할 때 시작/종료, 랩 출력, 다른 고정 명령, 변수 대입 순으로 확인한다. 수식 안에서는 `야하`, `이+히+`, `라+`를 `야`, `하`보다 먼저 인식한다. 알 수 없는 문자는 행과 열을 포함한 문법 오류다.

기본 최대 실행 횟수는 100,000회이며 종료 명령도 한 번으로 센다. 제한에 도달하면 실행 오류가 발생한다. 호스트는 `run(source, { maxSteps })`로 양의 안전 정수 제한을 지정할 수 있다.

## 예제

```text
야하!
우 이이이히
우라! 라
우 라 하
하아? 라
야하? 야야야야야야야
야하? 이이히
우라라!
```

`3`, `2`, `1`을 각각 한 줄에 출력한다. 네 번째 명령의 결과가 0이면 다섯 번째 명령에서 7번 종료 명령으로 이동하고, 0이 아니면 다섯 번째 명령을 건너뛰고 여섯 번째 명령에서 2번으로 돌아간다.
